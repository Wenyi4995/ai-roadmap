**视觉与多模态：从当前基础到一线公司 AI 工程岗位的完整路线**

更新：2026-10-20。规划周期约 18 个月；这是学习与求职的安排参考，不是录用承诺。每四周按实际成果调整进度。

**目标与起点**

主目标：视觉／多模态相关 Software Engineer、Machine Learning Engineer、Computer Vision Engineer 的实习或初级岗位。研究工程师作为进一步目标；研究科学家需要另外积累原创研究与通常更深入的研究训练。

你接触图像识别工作，学过 Java、C、高数和线性代数，尚缺深入编程与完整 AI 项目实践。仓库已有 Python、NumPy、Autograd、线性回归和少量算法练习记录；这些说明已经接触相关内容，熟练程度仍由独立验收确定。

学历、在读状态、毕业时间与目标就业地区尚未确认。此前“美国本科生”属于讨论假设，不作为个人履历事实。实际申请时核对学历、经验、在读／毕业窗口及工作资格要求。

本路线以视觉理解、图文对齐和视觉语言模型为主。图像生成、三维视觉、视频、CUDA 深度优化作为后续按岗位选择的分支。

**总安排**

| 阶段 | 参考时间 | 核心任务 | 过关时应达到的水平 |
|---|---|---|---|
| 0 | 第一周内 | 独立诊断，核对已有成果 | 确认可以跳过和需要补齐的内容 |
| 1 | 第 1—2 个月 | Python、工具链、数学恢复、算法入门 | 独立完成数据处理和基础机器学习程序 |
| 2 | 第 3—4 个月 | 机器学习、PyTorch、计算机系统基础 | 独立训练、验证、排错并复现实验 |
| 3 | 第 5—7 个月 | 计算机视觉、项目 A、基础部署 | 完成一个可深入讲解的视觉项目，开始争取相关机会 |
| 4 | 第 8—10 个月 | Transformer、图文对齐、项目 B | 独立构建与评估图文检索系统 |
| 5 | 第 11—14 个月 | 视觉语言模型、项目 C、研究合作 | 完成可信的微调与评测，形成技术报告或合作成果 |

18 个月含复盘和补缺空间。阶段验收提前通过即可进入下一阶段；未通过则延长 1—2 周并缩小任务。算法、英语、系统基础和求职准备从早期持续推进。

原仓库的 2027 年暑期实习和 2028 届招聘目标，可作为遇到匹配岗位时尽早争取的机会。申请节奏取决于真实在读／毕业条件和岗位开放时间，不等路线全部完成。

**时间怎么投入**

每天 5 小时核心学习：编程／项目 2 小时、课程与数学 1 小时、算法 1 小时、实验分析与英文记录 1 小时。项目阶段的课程时间可以转入实验。

能投入 8 小时时，额外 3 小时用于深入项目、系统实验、论文复现或合作；按当前阶段选一到两项。训练等待和被动观看不算高质量学习时长。

每周安排 6 天完整学习，另 1 天做 1—2 小时复盘或补缺，核心工作量约 31—32 小时；额外时间按精力增加。每周最多承诺 3 个主要成果。每四周采用“3 周推进＋1 周整合验收”。

只保留一门主课程与一条轻量基础辅线。课程按下文指定范围学习，不要求完成资源表内的所有完整课程。

**阶段 0：先独立验收已有基础**

用 2—3 天完成以下任务，可查官方 API 文档，核心实现不查看旧答案：

- 从空文件写出读取 CSV、检查缺失值、按规则拆分并输出统计结果的程序。
- 用 NumPy 写出线性回归预测、MSE 与梯度；在同一数据上与 PyTorch 对照。
- 独立写出训练／验证循环，说明梯度清零、训练模式与评估模式的区别。
- 做一道未见过的数组／哈希题和一道二分题，解释复杂度、边界与测试。

通过的内容直接缩短对应学习时间。卡住的点分别记录为概念不懂、API 不熟、调试不足或推导困难。仓库旧记录不覆盖、不自动升级为“熟练”。

**阶段 1：第 1—2 个月，建立独立编程能力**

学习内容：

- Python：函数、容器、迭代、异常、文件、模块、类的基本使用、虚拟环境、依赖与基本测试。
- NumPy：形状、广播、索引、矩阵乘法、向量化、随机数。Pandas 只学读取、分组、连接和缺失值处理。
- Linux／Git：目录、路径、进程、权限、环境变量、SSH 的概念与使用；提交、分支、差异、合并。已有 Windows 环境先用好，需要 Linux 实验时再选择 WSL 或远程环境。
- 数学恢复：矩阵乘法、秩、投影、特征值与 SVD 的直观含义；偏导、链式法则、梯度；条件概率、期望、方差、常见分布。
- 算法：数组、哈希、双指针、栈、队列、二分、复杂度。

主课程：[CS50P](https://cs50.harvard.edu/python/)，重点完成函数、异常、文件、测试与模块练习。工具辅线：[Missing Semester](https://missing.csail.mit.edu/)，选命令行、调试、Git、打包与代码质量。数学资料按薄弱点查阅资源表。

练习项目：把现有线性回归升级为命令行小项目，支持配置、固定数据划分、随机种子、训练曲线、保存参数和独立评估。两种实现必须使用同一数据和评估设置进行比较。

验收：

- 从空文件独立写出约 200 行量级的小程序，能拆成函数和模块；行数仅提示复杂度，不作成绩。
- 能解释每个主要数组／张量的形状，定位广播与维度错误。
- 能在新环境按 README 安装并运行项目，不依赖手动执行一串未记录的步骤。
- 算法参考累计 25—35 题；对陌生的基础题能说明思路并写出正确实现。
- 能推导线性回归梯度，解释学习率和随机噪声对结果的影响。

通过后的水平：可以独立处理数据与编写基础程序，具备进入深度学习训练的条件。

**阶段 2：第 3—4 个月，建立可靠的训练与实验能力**

主课程：[CS229 公开资料](https://cs229.stanford.edu/)，选线性／逻辑回归、最大似然、正则化、偏差与方差、模型选择与学习理论直觉；配合 [PyTorch 基础教程](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)。课程主题按可获得的公开版本学习。

学习内容：

- 机器学习：训练／验证／测试、交叉验证、数据泄漏、类别不平衡、指标、标准化、简单基线。
- 深度学习：MLP、反向传播、初始化、激活、交叉熵、优化器、正则化和学习率计划。
- PyTorch：Dataset／DataLoader、Autograd、模型模式、禁用梯度、设备、保存恢复、基础混合精度。
- 概率统计：最大似然、抽样、估计、置信区间、bootstrap 基本思路；区分训练随机性与测试样本不确定性。
- 计算机系统：数据表示、浮点数、缓存、进程／线程、虚拟内存、文件 I/O 与并发。
- 算法：链表、树、堆、递归、BFS／DFS。

练习：用 NumPy 实现两层网络及反向传播，用有限差分检查小规模梯度；用 PyTorch 对照。再训练一个小型图像分类器，分别制造学习率过大、标签错误、遗漏模式切换等故障并记录诊断。

验收：

- 独立编写训练、验证、检查点恢复与评估；验证不更新参数，也不意外污染训练状态。
- 能在极小样本上过拟合，说明这个诊断排除了什么、仍不能排除什么。
- 能区分优化问题、数据问题、过拟合和评价指标问题。
- 在相同数据与主要设置下比较至少 3 个有假设的实验，并清楚交代变量。
- 算法参考累计 55—70 题；能独立完成树遍历、二分与基本堆题。
- 能解释 GPU 显存与系统内存、进程与线程、计算与 I/O 瓶颈的区别。

通过后的水平：可以独立完成小型深度学习实验，能够解释并排查常见问题。

**阶段 3：第 5—7 个月，做深计算机视觉与项目 A**

主课程：[CS231n](https://cs231n.stanford.edu/)。独立完成分类、全连接网络、卷积、归一化和训练相关练习；自监督与多模态内容放入下一阶段。公开录像可能来自往年，按知识主题配套，不要求同一届全部材料都公开。

学习内容：CNN、残差连接、迁移学习、数据增强、视觉表示、ViT 入门；理解检测／分割的任务、IoU、NMS、mAP／mIoU。分类为主项目；另用一个短练习体验检测或分割，具体随目标岗位调整。

项目 A：图像识别的可靠性与部署。选择一个明确任务，例如有公开数据支持的图像分类。先用成熟预训练模型建立基线，再研究数据不足、类别不平衡或光照／模糊／背景变化中的一个问题。

最小实验矩阵：简单基线、冻结特征＋线性分类头、预训练模型微调；选一个主要因素做 2—3 组对照。比较时说明预训练、数据、输入分辨率、训练预算和超参数搜索范围，不能把所有差异归因于架构。

评价：准确率／宏平均 F1／分类别召回按任务选择；按定义好的场景切片分析。合成扰动只能支持对应扰动下的结论，不能当作真实跨场景部署证明。

工程：配置化训练、命令行入口、FastAPI 推理、基本输入检查、Docker、日志与小规模压测。学习 HTTP、TCP、超时、重试、状态码；SQL 学 SELECT、JOIN、GROUP BY、窗口函数与索引基础，用来分析样本和评测记录。

验收：

- 数据按实际场景合理划分；同主体、近重复和相邻帧问题已检查并说明。
- 独立完成训练与推理，能展示混淆矩阵、至少几类典型错误及改进取舍。
- 在同一协议下完成对照，关键结论用多个种子或适当的不确定性分析支持；预算不足时明确结论限制。
- 报告明确硬件、输入尺寸、batch、预热、GPU 同步、并发和测量边界下的延迟与吞吐。
- 新环境可重现小规模结果，模型权重与数据下载方法有记录。
- 能做 15—20 分钟项目讲解并接受追问。算法参考累计 90—110 题。

通过后的水平：有一个能证明完整视觉工程能力的项目，可开始争取符合资格的实习、实验室或初级合作机会。

**阶段 4：第 8—10 个月，理解 Transformer 并完成项目 B**

主课程：[CS224n](https://web.stanford.edu/class/cs224n/)，选 embedding、attention、Transformer、预训练与评测；多模态辅线：[CMU 11-777](https://multicomp.cs.cmu.edu/mmml-course/fall2026/)，选表示、对齐与融合。两者按指定主题使用，不并行完成整门课。

学习内容：tokenization、Q/K/V、多头注意力、mask、位置编码、归一化；视觉 patch、双编码器、相似度、对比学习、温度、负样本、跨注意力。

实现练习：小规模手写 self-attention 与对比损失，验证形状、mask、梯度和数值稳定性；从头训练微型模型只用于理解机制，真实项目使用公开预训练权重。

项目 B：图文检索与领域适配。以 CLIP 类双编码器为起点，构建图找文／文找图；先建立零样本基线，再选择提示词、训练数据或轻量适配中的一个因素研究。

评价：按图像与其相关文本组划分，定义一对多相关性与 Recall@K；准备容易混淆的负例，分析属性、数量、关系等失败类型。近似检索与精确检索都要有参照，区分模型误差与索引误差。对公开预训练模型无法排除预训练污染时说明限制。

系统：特征离线抽取、向量索引、批量推理、缓存、数据版本与模型版本、索引更新、端到端延迟与数据漂移监测。学习 DDP 的概念；有合适资源时做一次小规模多卡实验，没有则不虚构经验。

验收：

- 能从公式、张量形状与代码三个层面解释 attention 和对比学习。
- 可独立构建离线评测和在线检索流程，报告 Recall@K、延迟与内存。
- 能解释一个提升来自模型、数据、评测设置还是索引，并说明可能的混杂因素。
- 算法参考累计 120—150 题，覆盖图、回溯、贪心和基础动态规划。
- 从本阶段起每两周一次模拟面试；至少获得一次真实代码或项目审阅反馈。

通过后的水平：能够构建、评估与优化图文系统，具备进一步学习视觉语言模型的基础。

**阶段 5：第 11—14 个月，完成视觉语言模型与研究实践**

继续 CMU 11-777 与原论文，重点理解视觉编码器、连接模块、语言模型、视觉 token、指令微调、训练数据格式、LoRA、生成与幻觉评估。CS336 的资源估算、数据与评测章节可按需补充，不把完成整门 CS336 作为前置条件。

项目 C：视觉语言模型在一个窄任务上的可靠适配。可选图像问答、细粒度属性识别或简单场景理解；先做已有模型基线，再做参数高效微调。模型规模由显存、序列长度、图像分辨率与预算测试决定。

实验顺序：冻结任务与评分规则 → 固定 train／dev／test → 基座模型 → 提示词基线 → 同一基座的轻量微调 → 一个关键消融 → 独立评测与人工错误复核。

评价不能只依赖另一个语言模型评分。客观任务优先确定性评分；开放回答建立人工判分规则、标注歧义和复核样本。把错误区分为感知错误、知识缺失、指令不遵循与无图像依据的回答等，允许存在重叠。

研究实践：从与项目直接相关的论文中，选一项代码与预算可控的关键实验复现。区分复现作者结果、在不同条件下重新验证、提出新方法。写出问题、相关工作、方法、实验、失败结果和局限；争取实验室、开源维护者或有经验同行的反馈。

验收：

- 能画出所用 VLM 的数据流与训练参数范围，解释选择微调方式的原因。
- 基座与微调比较使用同样的推理／评价协议，开发集调参，测试集不反复用于选择方案。
- 保留成本、模型／数据版本与实验记录；结论包括适用范围和失败情况。
- 有一份短论文式报告与一个经反馈修订的项目；合作、论文或开源成果是否获得，由实际贡献决定。
- 算法参考累计 150—180 题，能解未见过的变体。没有提升时能给出可信的否定性结论。

通过后的水平：能够独立开展窄范围多模态实验，为研究工程或算法工程岗位提供更深入的能力证明。

**阶段 6：第 15—18 个月，形成求职材料并补齐岗位差距**

把 A、B、C 整理成 2—3 个有深度的代表项目。优先补齐目标 JD 要求；系统偏重岗位可把 C 的部分时间改为服务优化与更深入的性能分析，研究偏重岗位则增加复现和研究合作。

工程验收：

- 项目有配置、依赖、训练／评估／服务入口、关键正确性测试与基本 CI。
- 明确数据处理、模型版本、索引与服务的接口，说明失败恢复和回滚设计。
- 固定硬件与负载下报告质量、P50／P95 延迟、吞吐、显存／内存与成本口径；区分模型时间和端到端时间。
- 检查混合精度、编译或量化前后的输出质量，避免以不可接受的质量损失换取表面速度。

求职材料：一页英文技术简历、清楚的项目 README、项目演示、实验报告、可核查的贡献链接，以及个人贡献说明。数字只能来自实际测量；合作成果说明本人承担的部分。

模拟面试：近期完成 8—12 场有反馈的不同类型模拟，类型与目标岗位一致。缺陷修复后再复测。下面的标准是个人训练目标，不是公司的统一面试规则。

通过后的水平：有足够证据申请匹配岗位，能够在编码、基础、项目与设计讨论中稳定展示能力。录用仍受岗位资格、竞争、团队匹配和招聘数量影响。

| 第 8—10 个月 | GPU 计算／带宽、profiling、DDP、缓存与索引 | 分析预处理、拷贝、模型、检索各段耗时 | 能说明瓶颈及优化取舍 |
| 第 11—18 个月 | 数据管线、版本、监控、可靠性、ML 系统设计 | 为项目画架构并做故障演练 | 能讨论规模扩大和失败恢复 |

系统资料采用 [CSAPP](https://csapp.cs.cmu.edu/) 与 [OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/) 指定主题选读；网络使用 [Kurose/Ross 官方讲解](https://gaia.cs.umass.edu/kurose_ross/online_lectures.htm) 的应用层、传输层基础。SQL 和容器分别使用 [PostgreSQL 教程](https://www.postgresql.org/docs/current/tutorial.html)、[Docker 入门](https://docs.docker.com/get-started/)。

近期不把完整编译原理、完整操作系统内核、全部 CSAPP 实验或深入 CUDA 作为求职前提。目标岗位明确需要时再增加。C++ 对部署、视觉系统岗位可有价值，在 Python 熟练且出现岗位需求后增加。

**算法与面试准备安排**

算法每天约 45—60 分钟，陌生题先独立思考和实现，再看题解与复盘；隔 1 天、1 周、1 个月做变式或重做。题量只用来覆盖主题，不作为通过标准。

| 时间 | 专题 | 建议训练标准 |
|---|---|---|
| 第 1—2 个月 | 数组、哈希、双指针、栈、队列、二分 | 正确实现并解释复杂度 |
| 第 3—4 个月 | 链表、树、堆、递归、BFS／DFS | 不依赖背题完成基本变体 |
| 第 5—7 个月 | 图、并查集、回溯、贪心、基础 DP | 能定义状态、证明关键思路、处理边界 |
| 第 8—10 个月 | 混合题、限时编码 | 对未见过的典型中等题，争取 35—45 分钟完成分析、实现、测试 |
| 第 11 个月后 | 错题、陌生变体、模拟面试 | 多次模拟表现稳定，能边写边解释 |

面试按五类准备：

1. 编码：澄清输入、提出思路、分析复杂度、实现、测试与修正。
2. ML／视觉／多模态：损失与梯度、泛化、指标、CNN／ViT、attention、对比学习、VLM 数据与评测。
3. 项目深挖：问题、选择、基线、个人贡献、失败、可信度、性能与下一步。
4. ML 系统设计：从需求与数据出发，讨论训练、评估、服务、缓存、监控、迭代与失败恢复；深度按岗位等级调整。
5. 行为与沟通：合作、分歧、失败、主动解决问题、实验推翻预期的真实例子。

每个项目准备 2 分钟、10 分钟、30 分钟三个版本。第 5 个月起每月一次模拟；第 8 个月起每两周一次；面试前的 6—8 周每周安排 1—2 次针对性模拟。

**英语与论文**

每天保留约 20—30 分钟英文技术阅读，包含在每日记录时间内。早期读文档，中期读论文方法与实验，后期增加英文项目讲解。先求理解与准确表达，再追求流畅。

论文顺序：

- 第 5—7 个月：[ResNet](https://arxiv.org/abs/1512.03385)，连接残差结构与实际训练。
- 第 7—9 个月：[ViT](https://arxiv.org/abs/2010.11929)，连接 patch、表示和预训练条件。
- 第 8—10 个月：[CLIP](https://arxiv.org/abs/2103.00020)，连接对比学习与图文检索。
- 第 11—14 个月：[Visual Instruction Tuning](https://arxiv.org/abs/2304.08485)，连接视觉编码器、连接模块和语言模型。

这些是机制学习的起点，不代表当前最强模型。正式选型与研究前重新检索近期论文、代码与评测。每篇笔记回答问题、贡献、证据、限制与一个可运行的验证实验。课程作业按相应学术诚信规则完成；用于自我验收的核心实现保留独立完成能力。

**项目统一完成定义**

- 有明确任务、数据来源、使用范围、划分与污染检查说明。
- 有基线、配置、模型／数据版本、运行命令、随机种子和资源记录。
- 有事先说明的主要指标、误差切片、合理对照与结果限制。
- 有至少一个真实失败案例与诊断过程；结果没提升也如实记录。
- 有小规模可复现模式，以及数据、模型大文件的获取说明。
- 有简洁英文 README 与贡献说明；展示材料不包含无权公开的工作数据。
- 有外部代码／实验反馈与修订记录，能独立回答追问。

最早用 CPU、小数据验证代码；需要训练时先做短跑，测显存与速度，再确定模型规模和算力预算。可按月设计算资源上限，达到上限就调整实验。预算、显卡、模型和序列长度尚未确认，因此本路线不承诺具体硬件能完成某个固定规模训练。

**求职如何提前进行**

第 1 个月：建立岗位表，收集约 15—20 个实际 JD，记录职责、学历、经验、毕业时间、工作资格、技能、开放状态和来源日期。把不符合资格与技术差距分别标记。

第 3—4 个月：整理第一版简历与代码；在符合在读等条件时争取校内实验室、小型研究合作、开源任务或相关实习。申请数量由真实匹配决定。

第 5—7 个月：项目 A 验收后申请匹配的视觉、ML 工程、AI 软件与评测岗位；需要补足工程能力时，也考虑能实际接触 ML 系统的相关软件岗位。

第 8—14 个月：以项目 B／C 匹配多模态岗位，争取相关实习、研究工程合作或高质量开源贡献。投稿和 PR 是否接收不设为可保证的硬指标。

第 15—18 个月：根据回访与模拟结果修订定位，分批定向申请。没有回访先检查资格、岗位匹配与材料；有面试但编码失败就补编码；项目追问失败就补证据与技术深度。获得岗位和团队机会要分别确认，进入公司不自动保证分到理想团队。

核对依据：[DeepMind 对研究工程与研究科学家的区分](https://deepmind.google/careers/)、[Google 面向 BS/MS 的学生研究项目示例](https://www.google.com/about/careers/applications/jobs/results/132362676918461126-student-researcher-bsms-fall-2026)。岗位示例随时间变化，使用时重新核对；该学生研究项目并不提供直接转正路径。
